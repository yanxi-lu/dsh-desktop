# dsh-desktop 下一阶段功能设计

日期：2026-09-24。基线：本地桌面壳 0.4.9。本文为功能方案，不代表功能已经实现。

后续实施记录：用户确认开发后，已交付本地 0.5.0 实现。请以 [0.5.0 交付说明](release-0.5.0.md) 的已实现范围、测试记录和限制为准；本文保留原始设计，不能将候选功能视为全部完成。

## 1. 产品方向

将桌面壳定位为 Harness 的日常管理入口：让用户看清费用、找到会话、管理扩展、可靠升级，并能自行排查故障。对话、终端、文件预览等能力优先接入官方实现。

本地已经具备启动/重启、Node 安装、Harness 版本切换、余额查询、Token 统计、自定义单价、日期筛选、会话用量、分页及后台增量索引。下一阶段主要补齐准确性、恢复能力和跨功能联动。

官方 0.1.7-rc.1 已提供插件安装与配置、会话归档等能力，同时公告了 V4 会话日志和若干配置变更。应先验证所安装版本的能力再展示入口。[官方发布说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-rc.1)

## 3. 第一批：准确性和可靠性

### 3.1 计费规则升级

发现：本地 `src/main/usage.ts` 的价格核对日期仍为 2026-08-22；`isDeepSeekPeakTime()` 只按北京时间小时判断。当前官方文档已更新 Flash 单价、旧模型别名的路由说明，并规定周末及中国法定节假日全天按空闲时段计费。[官方定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

设计：

- 价目表按提供商、模型/别名、币种和生效区间保存，展示来源和核对日期。
- 历史调用默认使用当时生效的规则；“按当前价格重算”作为单独的模拟功能。
- 规则生效日期根据公告确认，不能把文档核对日期直接当作生效日期。缺少证据的区间标记为待核对。
- 官方分时计价支持时区、周末及法定节假日。缺失年度节假日资料时说明受影响的估价范围。
- 自定义价格按提供商/模型分别设置，支持生效时间；不被官方规则更新覆盖。
- 未识别模型单列“待配置价格”，不混入官方已匹配金额；用户可选择一个明确标注的估价规则。
- 首期由维护的版本化规则文件更新价格，保留上次有效规则。自动解析官网仅作为后续候选，解析结果未经校验不直接覆盖。

验收：跨价格调整日、北京时间跨日、工作日、周末和节假日都有可核对样例；同一筛选条件的概览、趋势、会话和导出金额一致。

### 3.2 统计兼容性与完整性检查

当前解析器依赖特定事件类型和字段。官方发布说明提到了 V4 日志，需要用对应版本样本验证；仅凭版本升级不能断言当前解析一定失败。

设计：

- 按日志格式选择解析适配器，记录适配器版本；升级解析器时使旧索引失效并重建。
- 统计区分“没有调用”“正在建立索引”“日志读取失败”“格式暂不支持”。
- 展示已识别会话数、读取失败数和数据更新至何时；格式未知不能静默显示零消耗。
- 保留原始 Token 元数据与估价规则分离，改价格不需要重新解压日志。
- 新增索引状态、最近扫描耗时、缓存占用及“重建统计索引”。重建只处理统计缓存。

验收：旧版与新版日志、追加写入、半帧、迁移和损坏缓存均有覆盖；统计不完整时页面明确标识。

### 3.3 更新中心与恢复

当前更新会停止服务后安装目标 npm 版本，失败后尝试启动现有安装；没有独立保存旧版本安装槽，因此不等于完整回滚。

设计：

- 分开显示桌面壳版本、Harness 版本和 Node 版本。
- 展示 npm 的发布通道与版本的预发布属性；`latest` 是分发标签，不能自动等同于稳定版。
- 同时展示 GitHub 发布说明和 npm 安装状态；只有源码标签的版本不能伪装成可直接安装的 npm 版本。
- 有正在运行的任务时提示受影响任务，提供“任务结束后更新”。
- 采用独立版本目录：下载并校验目标版本 → 备份必要配置 → 停止服务 → 切换版本 → 就绪与基本功能检查。
- 保留最近一个验证可用版本。新版失败时恢复旧安装槽；发生配置或数据迁移时，先检查备份与逆向兼容性，再决定是否允许自动恢复。
- 对可能迁移会话格式的升级，提供明确的数据备份选项和空间提示；不能仅回退二进制后宣称数据已恢复。
- 桌面壳自身的自动更新作为独立交付功能，需要配置用户所属的发布渠道、安装包校验和签名方案。

验收：断网、取消、依赖安装失败、端口冲突和新版无法就绪都有清晰结果；更新不会删除用户会话。

### 3.4 运行诊断

入口：“运行诊断 → 开始检查 → 查看问题 → 执行所选修复 → 复查”。

检查项：Node/npm 路径和版本、Harness 实际安装路径、监听端口及进程归属、本地服务就绪、网络/代理、目录是否存在及可访问、插件启动错误、统计日志格式。

每个结果包含状态、原因与操作。例如端口占用提供“查看占用进程”“选择可用端口”；目录失效提供“重新选择目录”。默认检查不发送计费模型请求，模型调用测试另列为用户主动操作。

诊断报告导出前可预览；默认只导出结构化诊断结果，移除 API Key、授权头和一次性启动 Token，私人路径使用占位符。

## 4. 第二批：日常使用体验

### 4.1 分栏工作台

侧栏建议：总览 / 用量与费用 / 会话 / 插件 / 更新与诊断 / 设置。

总览只放：服务状态、当前版本、今日费用与 Tokens、余额更新时间、最近会话以及需处理提醒。

- 每个模块独立加载。统计查询不等待 npm 或余额网络请求。
- 已有数据立即展示并带更新时间，后台刷新完成后更新；离线状态保留带日期的最近结果。
- 可见页面低频自动刷新，最小化或后台时暂停高频刷新；明确区分“已更新”和“正在更新”。
- 大表按页/虚拟滚动，窗口缩放合并图表重绘。保持现有图表风格，增加跟随系统的浅色/深色主题。

### 4.2 预算与提醒

- 设置本机统计范围的每日/月度预算，默认在 80% 和 100% 各提醒一次。
- 官方余额低于自定义阈值时提醒，展示查询时间；查询失败不能显示成零余额。
- 高消耗会话排行、与上一等长时间段的变化、缓存命中率变化。
- “预计还能使用多久”仅作为可选推算，说明样本天数和费用估算范围。
- 预算来自本机日志，不能代表同一 API Key 在其他机器或程序中的全部消费。第一版提供提醒，不承诺硬性限额或自动终止任务。

### 4.3 会话费用管理

- 搜索会话名称、ID，按日期、标签、项目分类和费用排序。
- 会话详情展示逐日用量、模型分布、费用趋势和最近调用；支持回到对应官方会话。
- 名称及项目关联从官方支持的元数据接口获取，用户开启后再加载；不为搜索默认索引提示词/回答全文。
- 先使用桌面壳本地标签建立分类；项目归属不明时显示“未分类”，不从私人路径猜测业务项目。
- 归档、恢复、删除复用官方能力并检查当前版本；删除需要展示范围，归档与删除分开。
- 没有稳定会话跳转接口时先提供复制会话 ID/进入官方会话列表，避免依赖脆弱的页面 DOM 操作。

### 4.4 导出与数据维护

- CSV/JSON 导出概览、模型、会话和调用明细，严格采用当前筛选条件。
- 导出附带统计时区、起止日期、币种、规则版本、数据完整性状态及“预估费用”标识。
- “重建缓存”和“删除会话”是不同操作。空间清理先展示可清理项，只自动处理可重建的缓存。
- 支持桌面偏好和自定义价格的备份恢复；包含凭据的迁移另行设计，不默认夹带密钥。

## 5. 第三批：插件和桌面联动

### 5.1 插件中心

第一阶段接入官方插件管理，展示已安装、可更新、异常、收藏四类；补充配置备份和升级后的可用性复查。对旧版 Harness 给出能力说明及可用升级路径。

后续的发现页展示真实来源、作者、包名、版本、许可证和兼容范围。安装前展示将运行的组件/依赖；不把社区插件写成经过安全审核的官方插件。任意包地址输入与经过整理的推荐目录分开。

实现依赖官方 CLI/API 的核实；通过适配层调用并进行版本测试，不直接修改官方正在使用的配置数据库。

### 5.2 桌面任务通知

完成、失败、等待用户操作三类通知；点击回到对应会话。支持免打扰、同一任务合并通知和隐藏预览内容。

通知状态应来自官方任务事件。日志修改时间只能表明文件变化，不能据此宣布任务完成。

### 5.3 配置方案

可保存“工作 / 个人 / 测试”的模型、提供商、定价、插件与数据目录组合。首期不同时运行多个 Harness 服务；切换前展示影响，运行任务期间延后切换。

待官方配置和运行接口稳定后，再评估多个独立实例及远程工作区。

## 6. 建议的交付顺序

1. 0.5.0 候选范围：价格规则、日志兼容性提示、发布通道展示和运行诊断；开始整理更新备份机制。
2. 后续可靠性版本：隔离版本安装与迁移恢复；用升级失败演练验证完整闭环。
3. 日常体验版本：分栏工作台、预算提醒、会话费用联动、导出。
4. 扩展版本：插件中心、桌面通知、配置方案。

验收以实际安装的 Harness 版本和真实数据为准。性能目标建议按固定硬件与数据规模记录：已有索引时常用查询 P95 不超过 300 ms；后台统计期间窗口持续响应；新数据可在刷新后核对。以上是后续验收目标，不是本方案新增的测试结论。

本轮只形成设计方案，功能开发与版本发布不包含在本文完成状态中。
